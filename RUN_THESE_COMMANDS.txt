Step 1: Start Database (takes ~10 seconds)
─────────────────────────────────────────────────────────────
make up-wait


Step 2-6: Run Complete ETL Pipeline in Docker Container
─────────────────────────────────────────────────────────────
make container-etl-load

This single command does:
  - Prepares CSV files (normalizes headers)
  - Bootstraps database schema (13 SQL files)  
  - Loads 4 CSV files in parallel (~32k rows)
  - Loads 366 SKU-VA mappings
  - Refreshes materialized views

Takes ~1-2 minutes total.


Step 7: Verify Row Counts (should show 366 in all 3 views)
─────────────────────────────────────────────────────────────
make counts


Step 8: Test STANDFAN SKU (should show 3114.40)
─────────────────────────────────────────────────────────────
docker exec app-postgres psql -U appuser -d appdb -c "SELECT \"SKU ID\", \"Amount Received\", \"Variance\" FROM mart.v_level1 WHERE \"SKU ID\" LIKE 'STANDFAN 16%' LIMIT 1;"


Step 9: Test 4 HOLE EGG PAN (should show 15284.44)
─────────────────────────────────────────────────────────────
docker exec app-postgres psql -U appuser -d appdb -c "SELECT \"SKU ID\", \"Amount Received\" FROM mart.v_level2a WHERE \"SKU ID\" = '4 HOLE EGG PAN-1288-636-92rxuDoq6U';"


Step 10: Shutdown (when finished)
─────────────────────────────────────────────────────────────
make down

═══════════════════════════════════════════════════════════════

EXPECTED RESULTS:
✓ Step 2-6: No errors, shows "Bootstrap complete" and row counts
✓ Step 7: Shows 366 rows in v_level1, v_level2a, v_level2b
✓ Step 8: Amount Received = 3114.40, Variance = 0.18
✓ Step 9: Amount Received = 15284.44
✓ Total time: ~2 minutes

WHAT container-etl-load DOES:
The container-etl-load target runs everything inside a Docker
container - NO Python, uv, or other tools needed on your machine!

It automatically:
1. Builds Docker image with all dependencies
2. Runs prep/bootstrap/load/mapping/refresh
3. Returns control when complete

═══════════════════════════════════════════════════════════════

TROUBLESHOOTING:
If Step 2-6 fails with "No rows found":
  1. Check CSV files exist: ls -la data/inc_data/*.csv
  2. Should see these 4 files:
     - external_accounts_2025-09.csv (or *_full.csv)
     - va_txn_2025-09.csv (or *_full.csv)
     - repmt_sku_2025-09.csv (or *_full.csv)
     - repmt_sales_2025-09.csv (or *_full.csv)
  
  3. If files are named *_full.csv instead of *_2025-09.csv:
     No problem! The ETL finds them automatically.

If "Connection refused":
  Run "make up-wait" first

If "Permission denied" (Git Bash Windows):
  Run "bash scripts/setup_gitbash.sh" (one-time fix)
